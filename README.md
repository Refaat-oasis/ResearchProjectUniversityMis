# ResearchProjectUniversityMis

# المنصة الإلكترونية للجان الفرعية للنزاهة الأكاديمية وأخلاقيات البحث العلمي
**(Research Ethics & Academic Integrity Sub-Committees E-Platform)**

منصة إلكترونية متكاملة ومؤمنة مبنية بتقنية **ASP.NET Core MVC (.NET 9)** و **Entity Framework Core** و **ASP.NET Core Identity**، مصممة لتحويل دورة عمل لجان أخلاقيات البحث العلمي بالجامعات بالكامل من المعاملات الورقية التقليدية إلى بيئة رقمية ذكية ومؤتمتة (**Paperless & Automated Workflow**) مع واجهة عربية كاملة (**RTL**).

---

## 🏛️ البوابات الرئيسية وأدوار النظام الأربعة

1. **مدير النظام العام (Super Admin)**:
   - لوحة المؤشرات المركزية وإحصائيات الجامعة.
   - إدارة كليات الجامعة ولجانها الفرعية.
   - تصنيفات الأبحاث وتعريف الحقول الديناميكية الإضافية لكل تصنيف (`FieldsDefinitionJson`).
   - تعيين وإدارة مديري لجان الكليات (`CollegeCoAdmins`).
   - دعوة وإدارة هيئة المحكمين المعتمدين وتفعيلهم أو تعطيلهم.
   - متابعة كافة مقترحات الجامعة، وأرشيف الشهادات الرقمية، وتقارير الجودة والاعتماد المؤسسي.
   - *(ملحوظة معمارية: لا يتدخل مدير النظام في الاعتماد النهائي أو إصدار الشهادات، وتقتصر صلاحيته على العرض والمتابعة).*

2. **مدير اللجنة الفرعية بالكلية (College Co-Admin)**:
   - إدارة طابور الفحص الشكلي الإداري للمقترحات (Screening Queue) ومتابعة مهلة الـ SLA (24 - 48 ساعة).
   - تسجيل الملاحظات الإدارية وتدقيق الوثائق والمرفقات الإلزامية.
   - التوزيع الآلي للمحكمين بناءً على تطابق التخصص الأكاديمي الدقيق وقلة أعباء التقييم المفتوحة، مع **الاستبعاد التلقائي لمنع تضارب المصالح**.
   - الاعتماد النهائي وإصدار الشهادات الأخلاقية الرقمية الممهورة بالختم والتوقيع الرقمي ورمز الـ QR (صلاحية حصرية لمدير لجنة الكلية).

3. **المحكم العلمي (Judge)**:
   - استعراض الأبحاث المسندة للتحكيم فقط (جلسة مستقلة ومحكمة).
   - نموذج التقييم الأخلاقي المحوسب:
     - حماية الخصوصية وسرية البيانات.
     - نسبة المخاطر والموازنة مع المنافع.
     - إجراءات ونماذج الموافقة المستنيرة.
   - إصدار قرار التحكيم المعتمد بالتوقيع الرقمي (`موافق` أو `طلب تعديلات`).
   - قاعدة الحسم الآلي بدون تصويت: اعتماد المقترح عند موافقة جميع المحكمين، أو طلب تعديلات في حال طلب أحد المحكمين ذلك مع إخفاء هوية المحكمين عن الباحثين.

4. **الباحث الأكاديمي (Researcher)**:
   - تسجيل حساب الباحث المقصور على النطاق المؤسسي المعتمد للجامعة (`@univ.edu.eg` / `@mis.edu.eg`) مع تأكيد البريد الإلكتروني.
   - نموذج التقديم الذكي وتعبئة الحقول التفاعلية حسب تصنيف البحث ورفع المستندات الإلزامية خارج المجلدات العامة (`App_Data/UploadedFiles`).
   - لوحة متابعة مسار المقترح التفاعلية (Status Tracker) عبر المراحل الخمس مع التحديث التلقائي الدوري.
   - رفع الوثائق والتعديلات المطلوبة لبدء جولات تحكيمية تالية.
   - استعراض وتحميل الشهادات الأخلاقية المعتمدة الصادرة.

5. **التحقق العام (Public Visitor)**:
   - صفحة التحقق السريع من صحة الشهادات الأخلاقية عبر مسح رمز الاستجابة السريعة (QR Code) أو البحث بالرقم المسلسل، مع عرض الحد الأدنى من البيانات الموثقة دون تسريب أي وثائق أو بيانات حساسة.

## 🛠️ التقنيات والمعايير المستخدمة

- **ASP.NET Core 9.0 MVC**: إطار العمل الأساسي.
- **Entity Framework Core 9.0**: إدارة قاعدة البيانات والعلاقات والفهارس الفريدة.
- **ASP.NET Core Identity**: إدارة الحسابات، الأدوار، الصلاحيات، Lockout، وتأكيد البريد.
- **QRCoder**: توليد رموز QR عالية الدقة للشهادات الرقمية.
- **Thin Controllers Principle**: وحدات تحكم خفيفة تنقل طلبات HTTP وتعتمد على مستودعات متخصصة (`Dedicated Repositories`) بدون Generic Repository.
- **UI/UX & RTL**: واجهة عربية أصيلة متوافقة مع `bootstrap.rtl.min.css` وتصميم خالٍ من النماذج المكررة (`ui-taste`).
- **Graphify**: بناء شجرة المعرفة ومخطط العلاقات المعمارية التفاعلي للمشروع (`graphify-out/`).

## 🧪 التحقق والاختبارات الآلية

يحتوي المشروع على حزمة اختبارات شاملة في `researchProject.Tests`:
```bash
dotnet test
```
تشمل 15 اختبار فحص معماري وتكاملي:
- قيود فرادة الجداول والملفات التعريفية.
- قيود النطاق المؤسسي للبريد وتأكيد البريد.
- منع تضارب المصالح وتوزيع المحكمين.
- إغلاق جولات التحكيم والانتقال الآلي بين الحالات.
- حصرية إصدار الشهادة لمدير لجنة الكلية واشتراط التوقيع الرقمي.
- التحقق العام وحماية البيانات.
