Dental Clinic Management System: Full Feature List
Platform: Desktop app (Tauri + React) with an ASP.NET Core API. It runs locally, with no internet required for now. Arabic UI (RTL), single page with sidebar, light and dark themes.

1. Users, Roles & Permissions
Super Admin (root) with full access to everything. Force a password change on first launch, and never ship a hard-coded superAdmin/superAdmin in production.
Admin with access to all features, who can:
Create and delete roles (Doctor, Assistant, custom roles)
Create users and rooms
Grant or deny any feature to any user
Permission-based access control: every feature, page and action (view, create, edit, delete) is a permission that can be assigned per user or per role.
Data scoping: each doctor only sees their own patients and appointments.
Special permissions: give a free session, give a discount, or charge extra.
Audit log: records who did what and when (edits, deletions, discounts, free sessions, price changes, permission changes, logins).
2. Patients
Profile: name, age, phone number
Treatment history (what was done before)
Chronic conditions (diabetes, hypertension…) and notes
Allergy warnings for medications and materials, shown prominently
Dental chart: a diagram of the teeth, with the treated tooth and treatment recorded per session
Images and X-rays: attach files to each patient (stored locally)
Fast search by name or phone number
Shown automatically in the session screen (history, chronic issues, notes), and the doctor can add notes live
3. Appointments
Create, edit and delete appointments
Categories (extraction, crown, filling…): the doctor can add, edit or delete them
Duration per category (Category X means Time X)
Appointment status: Booked, Arrived, In session, Completed, No-show, Cancelled, Late
Session timer:
Starts with the session
If the doctor doesn’t press “Done”, the engine records the overtime
Average-time module: learns the doctor’s real average per category and adjusts durations automatically (the doctor can switch it on or off)
Waiting list for cancellations: when a slot is freed, offer it to waiting patients
Rescheduling module: the admin defines options (after a week, after a month, custom)
4. Queue & Scheduling
The admin chooses the ordering method:
Simple queue (first come, first served)
If a patient is late, the next one enters and the late one goes after them
Multiple rooms and multiple doctors
Doctor timetable page: today’s sessions, count, and categories (for example, all extractions, or a crown session)
5. Treatment Plans
Multi-session treatments (implants, orthodontics, etc.) with a total cost
Planned sessions linked to the plan, with progress tracking
Remaining sessions and remaining balance per plan
6. Session Billing
The admin sets the session price (for example, 200 EGP)
The doctor adds tools and materials used in the session
Markup on tools: the admin sets the patient price above cost (cost 50, charge 60, so the 10 is income)
Total = session price + tools charged, and the doctor sees it before charging
Free session or custom price (lower or higher), only with permission
Prescriptions and receipts: printable prescription and receipt for the patient
7. Payments
Payment methods: Cash, Visa, InstaPay, Wallet transfer
Per-method totals shown separately (cash vs Visa vs InstaPay vs Wallet)
Installments and partial payments: the patient pays part now, the rest is tracked
Patient debts: outstanding balances and overdue follow-up
Daily cash closing: reconcile expected vs actual cash at end of day, with differences recorded
8. Inventory
Add tools and materials with cost
Pack-based purchasing: a purchase can be a box (for example, 30 units), and the admin or doctor can edit the pack size and quantity during the purchase. The system computes the unit cost (box price ÷ units).
Low-stock warnings: the doctor sets a warning threshold per item, with real-time alerts via SignalR
Expiry dates with alerts for materials near expiry
Inventory page for adding and managing tools
Automatic stock deduction when tools are used in a session
Stock movement history (purchased, used, adjusted)
9. Suppliers & Purchases
Supplier list
Purchase invoices (items, packs, prices, date)
Supplier payments: pay in full or partially, with the remaining balance owed tracked per supplier and per invoice
Supplier account statement (what was bought, paid and remaining)
10. Clinic Finance
Fixed costs: rent, water, electricity, and others
Salaries for staff
Doctor commission: a percentage per doctor from each session, used in payroll
Income vs. expenses overview
11. Reports & Dashboard
Doctor dashboard: income, loss, costs, and what the doctor pays for
Sessions per day and per category
Export to Excel and PDF
12. System & Data Safety
Automatic local backup of the database (scheduled, with restore)
Light and dark theme, Arabic (RTL)
Fully modular: any module can be enabled or disabled per user

Left out for now
Appointment reminders (WhatsApp/SMS) and online sync, since the system is offline-only. Both can be added later.

One technical note
Since it’s desktop and local, decide early where the database lives. If there’s one clinic PC, SQLite or local SQL Server works. If several PCs (reception, doctor rooms) need to share data, you need one machine acting as the server on the clinic’s local network. This affects how SignalR alerts work, so it’s worth deciding before you design the API.
